## Freshness and causal availability

`Reading` carries `observed_at`, `available_at`, source, status and a synthetic flag. Forecasts also require an issue time. The feature pipeline rejects observations or availability after the replay `as_of`, rejects nonhourly intervals, and prevents future-issued forecasts from entering features. For duplicate observation times, the latest available record wins.

Rain windows use exact hourly slots. A partial window remains missing; it is neither zero-filled nor scaled to a full accumulation. Latest observation age greater than two hours is stale; recent soil/level values must be within two hours. The dashboard exposes local observation time, availability time, age, 1/3/6/24h rainfall coverage, missing features and source IDs.

The archive adapter sets historical replay availability equal to the observation time **for demonstration**. It does not assert that retrospective reanalysis was actually available to authorities at that instant. No historical lead-time claim follows from this adapter.

## Reproducibility

Keep raw probe records, source URLs/checksums, processed files, `model-card.json` and training seed together. Data preparation is explicit: terrain download → `prepare_pilot.py` → `make_hillshade.py`. Do not rerun broad probes merely to view the dashboard: some scripts overwrite cached source evidence. Weather grids are model/reanalysis outputs, not installed sensors; static pilot locations are not a gauge network.
